# 2026-09-30 - Automatic device placement for Qwen3.8 27B GSQ-RCO

## 2026-09-30 - Delegate device placement in the Qwen3.8 27B GSQ-RCO profiles

**What**: Replace the fixed `--gpu-layers 999` with `--gpu-layers auto`, and
`--fit off` with `--fit on --fit-target 1024`, in the three
`qwen3.8-27b-gsq-rco` launchers. No other launcher changes. Context, batch,
ubatch, sampling and runtime arguments are untouched.

**Where**: `scripts/models/qwen3.8-27b-gsq-rco/start-agentic-65k-1024.cmd`,
`start-agentic-mtp-32k-1024.cmd`, `start-agentic-vision-32k-1024.cmd`, the
`qwen3.8-27b-gsq-rco` model card, and `docs/overview/inference-backend.md`.

**Why**: It is the only dense model in the catalog, so it is the only one without
a selective offload lever such as `--n-cpu-moe`, and its 10.96 GiB of weights
leave little margin on a 16 GiB card. Having the runtime resolve the placement
means it reduces offload instead of failing when other processes hold VRAM. The
delegation stays declared in the launcher, so the visibility requirement of
ADR-0001 is met by materializing the policy rather than the resulting numbers.
`gemma-4-12b-v2` already omits `--fit` and relies on its default, so this is not
the first profile set to leave the placement unresolved by name.

## Validation

- `Test-Llm.ps1 -ConfigurationOnly` passes for all 20 launchers.
- `llama-fit-params.exe` reports that `--fit` resolves the current 65.536-token
  configuration entirely on GPU (`-c 65536 -ngl -1`), so the placement itself is
  unchanged at the current contexts.
- Every flag used by these launchers was checked against the `--help` output of
  `llama-server.exe` itself. `--fit-print` is exposed by `llama-fit-params.exe`
  but is not a server flag, and is deliberately absent.
