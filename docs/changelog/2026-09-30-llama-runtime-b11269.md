# 2026-09-30 - Update llama.cpp runtime to b11269

## 2026-09-30 - Pin the Windows CUDA runtime to b11269

**What**: Update the official Windows x64 CUDA runtime from `b10502`
(`0adcc3bb5`, toolkit 13.3) to `b11269` (`cee37ffea`, toolkit 13.4). Because the
release no longer publishes a CUDA 13.3 Windows asset, the runtime directory
becomes `b11269-cuda13.4`. The installer verifies both release archives against
the SHA-256 digests published by GitHub for the release. All 20 existing
launchers now reference `b11269-cuda13.4`; no launcher was added, removed, or
otherwise reconfigured.

**Where**: `scripts/setup/Install-LlamaRuntime.ps1`, every existing
`scripts/models/**/start-*.cmd`, `runtimes/llama.cpp/b11269-cuda13.4/`,
`packages/llama.cpp/b11269/`, `docs/overview/inference-backend.md`, and the five
model cards that name the runtime directory.

**Why**: `b10502` does not expose `--n-cpu-ffn`, the CPU offload lever intended
for dense models. The targeted build adds it, which is what makes the
long-context work on `qwen3.8-27b-gsq-rco` tractable. The installed
`b10502-cuda13.3` runtime was retained as a rollback option and its package was
kept, so a revert needed no new download. Both were deleted on 2026-10-01; see
[the retired-runtime cleanup](2026-10-01-retired-runtime-cleanup.md).

## Validation

- Both downloaded archives matched the SHA-256 digests published by GitHub.
- `llama-server.exe --version` reported
  `0.5.0-dev (build 11269, commit cee37ffea)` on Windows x86_64.
- A static audit confirmed all 20 launchers reference `b11269-cuda13.4` with no
  residual `b10502-cuda13.3` reference, and that each file kept its original line
  endings.
- Functional validation of the profiles against the new runtime is pending. The
  previous changelog recorded a smoke test for the equivalent step; none was run
  here.
